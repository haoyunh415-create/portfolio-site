### 区块 ② 旗舰时间轴 — 7 个节点

每节点默认显示一句话结果，点击展开决策与权衡。

| # | 节点 | 展开内容 |
|---|---|---|
| 1 | 需求洞察 | 为什么选网文场景：800 章长篇的记忆断层 |
| 2 | 技术方案 | 为什么用渐进式摘要而非纯 RAG——长文档成本与上下文窗口权衡 |
| 3 | **Chrome 过审** | `host_permissions` 从通配符收窄到单域名：功能覆盖 vs 审核风险 |
| 4 | 合规与基建 | ICP 备案 · SSL · Nginx 反代 · systemd；为什么自建而非 Serverless |
| 5 | **分发渠道设计** | 国内用户装不了 Chrome 商店 → 必须做免梯 zip + 油猴版（覆盖 Via/Alook） |
| 6 | 商业化调研 | 蓝兔停止新签约；微信商户号需主体资质。**结论：个人开发者的第一道门槛是营业执照，不是技术。**（明确标注为调研结论，未实际办理） |
| 7 | ⚠️ **增长受阻** | 个位数用户 + 用户访谈发现 + 归因假设 + 下一步验证项 |

节点 3、5、7 是核心：3 证明懂平台规则，5 证明从真实约束倒推产品决策，7 证明敢看数据。

### 区块 ④ 验证与止损 — Hermes

```
假设：通用生图模型能做漫剧
  → PoC：CogView-3 + edge-tts + FFmpeg 全链路跑通
  → 结论：通用文生图无身份保持机制，角色必然漂移
  → 复盘：这是架构缺失，而非模型能力问题
  → 决策：止损，不投入 GPU 训练成本
```

**待补**：若时间允许，用可灵 `cref` API 补测一轮，叙事升级为"发现选型错误 → 补测验证 → 基于优先级判断暂缓"。

## 7. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 技术栈 | 纯 HTML + CSS + 原生 JS | 本周交付；唯一交互是时间轴展开，上框架是净亏 |
| 构建 | 无 | 无需构建步骤 |
| 部署 | Cloudflare Pages | 已在用、免费、国内可访问 |
| 域名 | `me.jianla.xyz`（CNAME）— **待确认，见 §12** | 自有已备案域名，比 github.io 更专业，本身即信号 |
| 仓库 | 新建 GitHub 仓库，Pages 自动部署 | 与现有工作流一致 |

### 文件结构

```
portfolio-site/
├── index.html          # 单页主体
├── styles.css          # 样式
├── main.js             # 时间轴展开交互
├── assets/             # 截图、图标
└── docs/superpowers/specs/
```

**约束**：单文件不超过 800 行。若 index.html 超限，**优先删内容而非拆文件**——超限说明文案冗长，而作品集的敌人正是冗长。手工合并 HTML 片段会引入易错的人工步骤，不采用。

## 8. 视觉方向

- 深色/中性底 + **单一强调色**
- 大留白，高信息密度
- **不加炫技动画**——AI 产品岗看信息密度，粒子特效只会显得在掩饰内容空洞
- 时间轴是唯一视觉主体
- 响应式：移动端单列堆叠（HR 常在手机上初筛）

---

## 9. 明确不做（YAGNI）

- ❌ 博客/文章系统
- ❌ 多语言切换
- ❌ 明暗主题切换（选定一套做好）
- ❌ 任何前端框架或构建工具
- ❌ 后端、数据库、访问统计后台
- ❌ AgentBench fork 展示
- ❌ 毕设作为"项目"展示（仅"在研"一行）
